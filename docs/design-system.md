# デザインシステム・UI規約

UIフレームワークは使わず、`frontend/src/components/` の共通コンポーネント＋CSS Modulesで構成しています。新しい画面・機能を追加する際は、まずここに書かれた規約と既存コンポーネントで実現できないか確認してください。

## デザイントークン

`frontend/src/styles/tokens.css` に集約。色・角丸・影・余白（`--space-1`〜`--space-7`）は必ずトークン経由で指定し、直接の数値・カラーコード指定は避けます。

## 共通コンポーネント一覧

| コンポーネント | 用途 |
|---|---|
| `Card` | コンテンツを囲む白背景カード。padding等は呼び出し側で指定 |
| `Button` | `variant`: primary / secondary / ghost / danger |
| `Badge` | `tone`: success / warning / info / neutral / danger |
| `PageHeader` | 画面タイトル。`title` / `description` / `actions`（右上の操作ボタン群） |
| `Modal` | ダイアログ。**デフォルトの「×」閉じるボタンは意図的に廃止**（下記参照）。閉じる手段はEscキー・背景クリック・明示的なボタンのみ |
| `Pagination` | `PAGE_SIZE = 10`固定。全ページで統一。`totalPages <= 1`なら自動的に非表示 |
| `EmptyState` | 「データが0件」の表示 |
| `ErrorState` | APIエラー時の表示。`onRetry`で再読み込みボタンを出せる |
| `Skeleton` / `SkeletonTable` / `SkeletonCards` | ローディング中のプレースホルダー。詳細は下記 |
| `FormError` | フォーム・ダイアログ内のエラーメッセージ表示（赤背景） |
| `FloorMap` | フロアマップ画像表示（バックエンドから取得） |
| `MonthCalendar` | 予約カレンダー（月表示、複数日・複数週にまたがる予約のバー表示に対応） |
| `UserMenu` | ヘッダー右上のユーザードロップダウン。ルートに応じて表示項目が変わる |

## アイコン

`lucide-react` に統一済み。絵文字アイコンは使用しない。ナビゲーションアイコン・ボタン内アイコン（編集=`Pencil`、削除/キャンセル=`Trash2`、追加=`Plus`、エクスポート=`Download`、インポート=`Upload`）は既存ページからサイズ（`size={14}`〜`16`）ごと踏襲すること。

## 一貫性ルール（何度も指摘されて確立したもの）

1. **名前 = リンク**: 一覧のエンティティ名は、それ自体がそのエンティティの詳細ページへのリンクになる。「詳細 →」のような別リンクは作らない。
2. **一覧は閲覧のみ、編集・削除は詳細画面で**: 詳細ページが存在するエンティティは、一覧に編集・削除ボタンを置かない。
3. **右側は操作欄**: `PageHeader`の`actions`（右上）には本当の操作（編集・削除ボタン等）だけを置く。ステータス・権限などのバッジは情報として`<dl>`の先頭項目に入れる（右上に置かない）。
4. **ダイアログの右端は必ず安全な操作**: 確認・編集ダイアログのボタン列は、破壊的操作（削除・キャンセル）を右端に置かない。右端は「閉じる」「戻る」などの安全な操作にする。
5. **一覧のカラム順**: 予約系のテーブルは「利用目的」を先頭カラムにする。
6. **ページネーション**: `PAGE_SIZE = 10`で統一。
7. **空の任意項目の表示**: カードやテーブルで「現在」「次回」のような任意のライブステータス項目が空の場合、文章（「利用なし」等）で埋めずに `-` で表示する。省略すると高さが揃わずレイアウトが崩れるため。

## ローディング・エラー表示

- 画面全体を覆うローディング表示（真っ白のブランク画面）は禁止。ヘッダー・サイドバーなどのレイアウトは常に表示したまま、データに依存する箇所だけをスケルトンに差し替える。
- テーブル一覧: `SkeletonTable columns={N}`
- カードグリッド: `SkeletonCards count={N}`
- 詳細ページ: `Skeleton`を組み合わせてカードの概形を表現
- エラー時も同様に、該当箇所だけを`ErrorState`に差し替える（`reload()`を`onRetry`に渡す）。

## Modalの「×」を廃止した理由

初期実装ではモーダル右上に「×」閉じるボタンがあったが、そこに編集・削除アイコンを置く案が出た際に「閉じるボタンと紛らわしく誤操作を誘発する」という結論に至り、デフォルトの「×」自体を廃止した。閉じる手段はEscキー・背景クリック・画面下部の明示的なボタンのみに統一している。ヘッダー領域に何かアイコンを置きたい場合は`Modal`の`headerActions`props経由で個別に用意すること（安易に「×」の位置を復活させない）。
